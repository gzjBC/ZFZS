# ZFZS 项目整合与跨平台进度书

更新时间：2026-10-15（GitHub 技术调研于 2026-10-08；验证于 2026-10-15）

## 1. 项目目标

项目已从“只能通过浏览器访问的本地 Web 工具”调整为“桌面客户端优先、Web 能力作为可选研发分支”的结构。核心目标是：

1. Windows 上可以从桌面图标直接打开原生窗口；
2. macOS 上可以继续开发并构建 `.app`；
3. 日常使用不依赖 Docker、Node.js 或浏览器；
4. 保留原 ZFZS 仓库的 Bangumi、季度新番、AI 推荐与 PostgreSQL 实现，逐步迁入桌面端；
5. Windows 与 macOS 各自在本机打包，避免不可靠的跨系统交叉编译。

## 2. 合并结果

两个代码基线已合并为单一仓库：

| 区域 | 定位 | 技术栈 | 运行依赖 |
|---|---|---|---|
| `desktop/` | 主产品，原生桌面追番客户端 | Python 3.13、Tkinter、SQLAlchemy、SQLite、Requests、Playwright | Python；打包后无需 Python |
| `web/` | 可选实验端与功能参考实现 | Next.js 16、React 19、TypeScript、Tailwind 4、PostgreSQL 16 | Node.js、PostgreSQL；推荐用 Docker |
| `.github/workflows/` | Windows/macOS/Linux 自动验证 | GitHub Actions | GitHub 托管运行器 |

这不是把两套数据库和 UI 强行耦合。桌面端继续使用 SQLite 保证“点开即用”，Web 端保留 PostgreSQL 以承载日历、季度与 AI 推荐实验。两端优先共享数据源约定和业务规则，待桌面能力稳定后再决定是否抽取公共服务。

## 3. 已完成工作

### 桌面端

- 新增 Tkinter 原生窗口，不再要求浏览器作为主界面；
- 支持番剧搜索、加入追番、进度增减、暂停/继续、标记完成、提醒与手动添加；
- 接入 Bangumi 官方 API 作为默认搜索源，并保留稀饭动漫抓取作为备选；
- 搜索导入按“来源 + 条目 ID”去重，重复导入不会重置用户进度；
- 修复动态页面等待、标题解析、状态与年份提取、提醒日期映射等问题；
- 数据目录改为操作系统标准用户目录，代码仓库可以在 Windows 与 macOS 间直接迁移；
- 首次源码运行可复制旧 SQLite 数据，保留原数据库，不覆盖已有用户目录数据库；
- 增加 Windows 桌面快捷方式、Windows/macOS 启动脚本与 PyInstaller 打包脚本；
- macOS 自动识别 Chrome/Edge 路径，Bangumi 搜索本身无需浏览器。

功能合并范围：Bangumi 搜索已迁入桌面端；日历、季度新番、评分驱动的 AI 推荐仍保留在 `web/`。两端的个人追番数据库尚不自动互通。提醒目前是应用内列表，没有后台系统通知。

### Web 端

- 完整保留原仓库的放送日历、季度新番、追番清单和 AI 推荐；
- 保留 Next.js API Routes、Bangumi 客户端、Qwen/DeepSeek 回退与 PostgreSQL 数据层；
- Docker Compose 继续只启动 `postgres:16-alpine`，不成为桌面客户端的运行前提。

### 工程化

- 仓库调整为 `desktop/` + `web/` 的清晰单仓结构；
- 增加跨平台 CI：Windows/macOS 验证桌面端，Ubuntu + PostgreSQL 验证 Web 端；
- 增加手动打包工作流，分别构建 Windows 与 macOS 产物并保存为 Actions artifacts；
- Python 依赖区分运行依赖与 PyInstaller 开发依赖；
- 本地数据库、虚拟环境、构建产物和临时克隆均排除在 Git 之外。

## 4. Docker 现状与建议

本机已安装 Docker Desktop，Docker CLI 版本为 29.5.3；10 月 15 日在沙箱外检查时 Engine 仍在 20 秒后超时，因此当前无法可靠列出或复用本机镜像与容器。仓库中可确认、且对当前需求真正有价值的 Docker 技术栈是：

- `postgres:16-alpine`：供 `web/` 的追番清单与测试数据库使用；
- 命名卷：持久化 PostgreSQL 数据；
- 健康检查：在应用启动前确认数据库可连接。

不建议把 Tkinter 桌面 GUI 放进容器。容器更适合无界面的数据库、同步服务和未来的 API 服务；原生窗口、系统通知和本机快捷方式应直接运行在宿主系统。

## 5. GitHub 技术调研

以下项目与当前路线直接相关：

| 项目 | 用途 | 结论 |
|---|---|---|
| [bangumi/api](https://github.com/bangumi/api) | 官方番剧搜索、日历与条目数据 | 已作为桌面端默认搜索源；比页面抓取更稳定 |
| [PyInstaller](https://github.com/pyinstaller/pyinstaller) | 打包 Windows 可执行程序与 macOS `.app` | 已接入；必须分别在 Windows 和 macOS 构建 |
| [Qt for Python / PySide6](https://github.com/pyside/pyside-setup) | 更成熟的跨平台桌面 GUI | 作为下一阶段 UI 升级候选；当前先保留迁移成本更低的 Tkinter |
| [CustomTkinter](https://github.com/TomSchimansky/CustomTkinter) | 改善 Tkinter 外观和 DPI 一致性 | 可做渐进式美化，优先级低于数据源和打包稳定性 |
| [desktop-notifier](https://github.com/samschott/desktop-notifier) | Windows/macOS/Linux 原生通知 | 适合下一阶段提醒落地；macOS 正式通知需签名应用 |
| [uv](https://github.com/astral-sh/uv) | 跨平台 Python 环境和依赖管理 | 适合开发环境提速，暂不强制用户安装 |
| [APScheduler](https://github.com/agronholm/apscheduler) | 后台定时检查更新与提醒 | 若引入应固定稳定版 v3，避免直接依赖仍在变化的 v4 |
| [actions/setup-python](https://github.com/actions/setup-python) | GitHub Actions 的 Python 矩阵 | 用于 Windows/macOS CI |

## 8. 开发约定

- 默认开发和发布目标是 `desktop/`；
- 日常桌面使用不要求启动 `web/` 或 Docker；
- 新功能先抽成无 UI 的服务模块，再接 Tkinter 或未来 PySide6；
- 对外部数据源必须保留超时、错误提示和可替代路径；
- 所有跨平台路径使用 `pathlib` 或操作系统标准目录，不提交用户数据库与密钥。


本地另存完整历史包 `.tmp/ZFZS-transfer.bundle`，可在网络恢复前复制到 Mac，然后执行：

```bash
git clone ZFZS-transfer.bundle ZFZS
cd ZFZS
git remote set-url origin https://github.com/gzjBC/ZFZS.git
cd desktop
./scripts/run_desktop.sh
```

Git 历史包只含源码和文档，不含虚拟环境、打包产物或个人追番数据库。应用本体在 `desktop/dist/ZFZS-Anime-Tracker/`，需保留整个目录使用。
